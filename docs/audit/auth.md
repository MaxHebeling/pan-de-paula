# Auditoría 360° — Autenticación, autorización, seguridad y administración

- **Rama:** `audit/auth` (rebasada sobre `main` 576df36, incluye 0080 + `_post_migrate.sql`)
- **Fecha:** 2026-09-12
- **Entorno:** solo local. Dev server `next dev -p 3110` y `next start -p 3111` para las cookies de producción. Base de desarrollo `pdp_dev_audit_auth` y bases de prueba `pdp_test_audit_auth` y `pdp_test_audit_auth_auth`. Producción no se tocó.
- **Principio:** nada cuenta como PASS sin evidencia (petición HTTP, consulta SQL, test unitario/SQL o E2E). Las server actions se invocaron **directamente** (POST con `Next-Action` y la cookie de cada rol), no solo desde la UI. El formato de invocación se validó con un control positivo del owner.

El modelo de seguridad de base es sólido: argon2id con parámetros OWASP, tokens de 256 bits guardados como sha256, cookie `httpOnly`/`Lax`/`Secure` en producción, permisos recalculados en cada request, `requireSession(permiso)` en **todas** las server actions del CRM, RLS + `pdp_app` y jerarquía por rango. Los bugs estaban en los bordes: cabeceras no confiables, carreras, contadores, rutas públicas, gating de `/api` y vida de la sesión.

### 3.3 Recorridos E2E (`apps/admin/e2e/audit-auth.spec.ts`, mobile + desktop)

1. Rutas privadas y `/api` sin sesión, más cabeceras.
2. Login incorrecto e inexistente idénticos; login OK; flags de la cookie.
3. Open redirect (`//`, `/\`, `https:`, `/api/`), y `next` legítimo respetado.
4. CSRF cross-origin al logout rechazado; logout real; la cookie vieja en otro navegador rebota.
5. `/recuperar` indistinguible exista o no la cuenta, también bajo rate limit.
6. Alta de caja → contraseña temporal una vez → duplicado → primer login forzado (páginas y `/api` bloqueadas) → toda la política → páginas y endpoints prohibidos → menú filtrado → auditoría INSERT/PASSWORD_CHANGED con el actor → filtros basura → desactivar cierra sesión y login rechazado.
7. Alta de producción → aterriza en `/pedidos` → enlace de reset → uso en otro navegador → sesión previa revocada → clave vieja inválida → token de un uso → auditoría `PASSWORD_RESET_LINK`/`PASSWORD_RESET` → cerrar todas las sesiones.
8. Jerarquía: owner no ve «Super Admin», no gestiona al super_admin ni por URL, no se edita rol/estado a sí mismo.
9. Configuración: guardar → refrescar → persiste → auditado; nombre inválido; `map_url=javascript:` rechazado; punto de retiro auditado; restauración.
